## 1. 总则

### 1.1 三条最高原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **注释解释「为什么」，不解释「是什么」** | 代码本身已经说明了"做了什么"，注释要补充代码无法表达的决策理由、业务背景、坑与取舍 |
| 2 | **命名即注释** | 好名字可以消灭 80% 的注释需求。写注释前先问自己：能不能改用更好的命名？ |
| 3 | **自用项目不追求注释覆盖率，追求关键位置零缺失** | 接口/UseCase/算法/适配代码必须写；简单的映射与 getter 不写 |

### 1.2 注释密度建议

| 位置 | 要求 |
|---|---|
| `domain/repository` 接口方法 | **100%** |
| `domain/usecase` 的 `invoke` | **100%** |
| `domain/calculator` 纯计算函数 | **100%** |
| `data/parser` 正则与解析 | **100%** |
| `data/capture` ROM 适配分支 | **100%** |
| Entity 中有业务含义的字段 | **100%** |
| ViewModel 公开方法 | 80% |
| 私有小函数、简单映射、Getter | 不强制 |
| 实现内部关键行 | 5%~15%（只写"为什么"） |

**执行口径**（2026-09 全仓清理时定下，新代码照此执行）：

1. 一个结论**压到 1~2 行**；写超过 2 行就该自问「哪一句是必须留的」；
2. **同一理由只写一处** —— 跨文件重复的设计论证收敛到主文件，他处一行指路（`见 XxxKeepAlive 的文件头`）；
3. 行注释标记统一用 §4.3 的六个前缀（`// NOTE:` `// PERF:` `// HACK:` `// ROM:厂商` `// TODO:` `// FIXME:`），
   不再混用 `⚠️` / `注意：` / 无前缀的「说明」；
4. 复述代码、复述参数类型、getter 语义、教程式背景一律不写。

## 2. 命名规范

### 2.1 通用规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 包名 | 全小写，无下划线，单数 | `com.kai.bill.domain.usecase` |
| 类名 / 接口 | `PascalCase`，名词或名词短语 | `BillRepository`、`GlassCard` |
| 接口实现 | 接口名 + `Impl`，或语义前缀 | `LocalBillRepository`、`CategoryRepositoryImpl` |
| 函数 / 变量 | `camelCase`，动词开头（函数） | `recordBill()`、`monthSpentCents` |
| 常量（`const val`） | `SCREAMING_SNAKE_CASE` | `DEFAULT_BLUR_RADIUS_DP` |
| 枚举类 | `PascalCase` 单数 | `BillType`、`AppPalette` |
| 枚举常量 | `SCREAMING_SNAKE_CASE` | `EXPENSE`、`FOLLOW_SYSTEM` |
| 密封类子类型 | `PascalCase` | `Outcome.Success` |
| 类型参数 | 单个大写字母，有意义时用单词 | `<T>`、`<reified T : Bill>` |
| 测试类 | 被测类名 + `Test` | `BudgetCalculatorTest` |
| 测试方法 | `被测方法_预期结果_条件`（反引号包裹） | `` `calculate_returnsNegative_whenOverBudget` `` |

### 2.2 本项目强制命名约定 ⚠️

| 场景 | 规则 | 正例 | 反例 |
|---|---|---|---|
| **金额变量** | 必须带 `Cents` 后缀，类型 `Long` | `amountCents`、`monthSpentCents` | ~~`amount`~~ ~~`money`~~ |
| **时间戳变量** | 带 `Millis` 或 `At` 后缀 | `createdAt`、`smsLastScanMillis` | ~~`time`~~ ~~`date`~~ |
| **返回 `Flow` 的函数** | 以 `observe` 开头 | `observeBills()`、`observeBudgetProgress()` | ~~`getBills()`~~ |
| **一次性查询（suspend）** | 以 `get` / `find` 开头 | `getBillById()` | ~~`observeBillById()`~~ |
| **写入操作** | 以 `save` / `update` / `delete` / `insert` 开头 | `saveBudget()` | ~~`setBudget()`~~ |
| **Boolean 变量** | `is` / `has` / `can` / `should` 开头 | `isOverBudget`、`countInStats` | ~~`over`~~ ~~`flag`~~ |
| **集合** | 复数形式 | `bills`、`categories` | ~~`billList`~~ |
| **ViewModel 状态** | 统一 `XxxUiState` | `HomeUiState` | ~~`HomeState`~~ ~~`HomeViewState`~~ |
| **Composable 函数** | `PascalCase`，名词性，不加 `Composable` 后缀 | `GlassCard`、`BillItem` | ~~`glassCard()`~~ ~~`BillItemComposable()`~~ |
| **Composable 参数 Modifier** | 必须是第一个可选参数，命名 `modifier` | `fun GlassCard(modifier: Modifier = Modifier)` | — |

### 2.3 资源命名

| 类型 | 规则 | 示例 |
|---|---|---|
| String | `模块_语义` | `home_budget_remaining`、`error_amount_negative` |
| Drawable | `ic_语义` / `bg_语义` | `ic_category_food`、`bg_glass_card` |
| 颜色（XML） | 极少使用，颜色统一写在 `PaletteDef.kt` | — |

> **本项目颜色全部定义在 `core/design/theme/PaletteDef.kt` 的 Kotlin 代码中**（因为要做 3 套主题 × 深浅双模的动态切换），**禁止**在 `colors.xml` 中定义业务颜色。

## 3. 函数级注释（KDoc）

### 3.1 什么时候必须写

✅ **必须写 KDoc**：

- 所有 `interface` 中声明的方法（`Repository`、`BillSource` 等）
- 所有 `UseCase` 的 `invoke`
- 所有纯计算/纯函数（尤其是 `domain/calculator`）
- 涉及正则、金额、时间换算的函数
- 有非显而易见的边界条件或副作用的函数
- 会抛异常的函数
- 对外暴露的公共工具函数（`core/common`）

❌ **可以不写**：

- 一行实现的私有小函数
- 明显的映射函数（`BillMapper.toDomain()`）
- 自动生成的代码
- 测试函数（改用函数名表达意图，必要时用 `// Given / When / Then` 行注释）

### 3.2 标准模板

```kotlin
/**
 * 一句话概括：动词开头，说明这个函数做什么，以句号结尾。
 *
 * 可选：补充说明业务背景、算法思路、使用场景。
 * 空一行后写细节，可以有多段。
 *
 * @param 参数名 参数说明，必须说明**单位**和**取值范围**（如有）
 * @param 参数2 说明
 * @return 返回值说明，说明单位和可能的特殊情况
 *
 * @throws 异常类型 什么条件下抛出
 *
 * @see 相关函数 交叉引用
 */
```

### 3.3 完整示例

#### 示例 1：UseCase（接口 + 实现）

```kotlin
/**
 * 记录一笔账单并写入本地库。
 *
 * 这是所有账单录入的**最终**落库入口：手动记账、通知解析、短信解析
 * 最终都会汇聚到这里，因此本类承担了统一的字段归一化职责。
 *
 * 注意：**本函数不做去重**。去重职责在 [BillIngestor]，
 * 因为不同来源的去重策略不同（通知与短信需时间窗判重，无法确认时进待审核）。
 *
 * @param bill 待保存的账单。[Bill.id] 为 0 时表示新增，否则为更新
 * @return 保存后的账单 ID；新增时返回数据库自增 ID
 */
class RecordBillUseCase @Inject constructor(
    private val billRepository: BillRepository,
    private val clock: Clock
) {
    suspend operator fun invoke(bill: Bill): Long {
        // 记录时间与交易时间是两个概念：用户可能在 3 号补记 1 号的消费，
        // 统计必须按交易时间归月，所以这里只补 createdAt，不碰 bill.time
        val now = clock.nowMillis()
        return billRepository.save(bill.copy(createdAt = now, updatedAt = now))
    }
}
```

#### 示例 2：纯计算函数（预算算法）

```kotlin
/**
 * 计算本月预算进度与今日可用额度。
 *
 * 支持两种日预算模式：

 *   昨天省下的钱会自动补给今天，符合"心理账户"直觉
 * - [DailyMode.FIXED]：今日可用 = 固定日预算，与月预算互不影响
 *
 * 算法前提：传入的 `monthSpentCents` / `todaySpentCents` 已过滤掉
 * [Bill.countInStats] 为 false 的账单（转账、还款等），否则会重复计算。
 *
 * @param monthlyBudgetCents 月预算金额，单位「分」；为 0 表示用户未设置预算
 * @param monthSpentCents 本月已支出，单位「分」，恒为非负
 * @param todaySpentCents 今日已支出，单位「分」，恒为非负
 * @param daysRemaining 本月剩余天数（含今天）
 * @param mode 日预算计算模式
 * @return 预算进度快照，含已用/剩余/今日可用/是否超支
 *
 * @throws IllegalArgumentException 当金额为负数，或 [daysRemaining] 小于 1 时抛出
 *
 * @see DailyMode
 */
fun calculate(
    monthlyBudgetCents: Long,
    monthSpentCents: Long,
    todaySpentCents: Long,
    daysRemaining: Int,
    mode: DailyMode
): BudgetProgress { ... }
```

#### 示例 3：Repository 接口

```kotlin
interface BillRepository {

    /**
     * 观察指定时间范围内、满足筛选条件的账单列表。
     *
     * 返回的是**热流**：数据库发生任何变更时会自动重新发射，
     * UI 层无需手动刷新。生命周期由调用方（ViewModel）的协程作用域管理。
     *
     * @param range 时间范围，由 [TimeRange] 生成（日/月/年）
     * @param filter 组合筛选条件（类型/分类/账户/是否计入统计），为 null 表示不筛选
     * @return 按交易时间**倒序**（最新在前）排列的账单流
     */
    fun observeBills(range: DateRange, filter: BillFilter?): Flow<List<Bill>>

    /**
     * 保存一笔账单（新增或更新）。
     *
     * @param bill 待保存账单；[Bill.id] 为 0 时新增，否则更新
     * @return 保存后的记录 ID
     */
    suspend fun save(bill: Bill): Long
}
```

### 3.4 KDoc 书写要点

| 要点 | 说明 |
|---|---|
| 第一行是摘要 | IDE 折叠时只显示第一行，必须能独立表达语义 |
| 摘要用第三人称 | ✅ "计算预算进度" ❌ "这个函数用来计算…" |
| 参数说明单位 | `@param amountCents 金额，单位「分」` — 金额/时间必须写单位 |
| 说明取值范围 | `@param daysRemaining 剩余天数，最小值为 1` |
| 用 `[Name]` 交叉引用 | `[Bill.countInStats]`、`[DailyMode.ELASTIC]` 会生成超链接 |
| 说明「不做什么」 | 如"本函数不做去重"，避免调用方误解职责 |
| 不写实现细节 | 注释描述契约，实现改了注释不该失效 |

## 4. 关键行注释

### 4.1 六类必须写行注释的场景

#### ① 解释「为什么」—— 最高频、最有价值

```kotlin
// 月末最后一天：把剩余额度全部给今天。
// 若继续按 daysRemaining=1 计算虽然结果相同，但显式处理能避免月末跨天的除零风险
val safeDays = daysRemaining.coerceAtLeast(1)

// 交易时间与记录时间必须分开：用户在 3 号补记 1 号的消费时，
// 统计要按 1 号归月，否则月度报表会错
time = parsedTradeTime
```

#### ② 标注坑 / 反直觉代码

```kotlin
// 注意：Room 的 @Transaction + Flow 组合下，首次发射会早于事务提交，
// 这里必须用 distinctUntilChanged 过滤掉中间态，否则 UI 会闪一下空列表
return dao.observeBills().distinctUntilChanged()

// 坑：支付宝通知在折叠状态下 EXTRA_TEXT 为空，只有 EXTRA_BIG_TEXT 有内容，
// 必须两个都取，否则多笔合并时会漏解析
val text = extras.getCharSequence(EXTRA_TEXT) ?: extras.getCharSequence(EXTRA_BIG_TEXT)
```

#### ③ 解释魔法值 / 正则 / 常量

```kotlin
// 60 秒时间窗：同一笔消费的通知与短信可能相差几秒到达，
// 窗口设太大（>5min）会误判连续的两笔相同金额消费
private const val DEDUP_WINDOW_MILLIS = 60_000L

// 匹配："您尾号1234的卡于10月01日15:30消费人民币25.00元"
//       "【招商银行】尾号1234账户10月01日支出（RMB）25.00"
private val BANK_SMS_REGEX = Regex("""
    (?:尾号)?(\d{4}).*?           # 卡号后四位
    (?:消费|支出|支付)             # 动作词，覆盖不同银行话术
    .*?([\d,]+\.?\d{0,2})\s*元?   # 金额，可能带千分位逗号
""".trimIndent(), RegexOption.COMMENTS)
```

#### ④ 平台 / ROM 适配分支

```kotlin
// ROM:vivo —— OriginOS 的「通知使用权」入口与 AOSP 不同，
```

### 4.2 禁止写的注释 ❌

```kotlin
// ❌ 同一段理由在多个文件里各写一遍（收敛到主文件，他处一行指路）
// ❌ 把「为什么」写成小作文（超过 2 行通常说明混进了复述与常识）
// ❌ 复述代码（代码已经说清楚了）
i++                     // i 加 1
val list = mutableListOf<Bill>()   // 创建一个列表
if (amount > 0) { }     // 如果金额大于 0

// ❌ 注释掉的死代码（删掉它，用 Git 找回）
// val oldResult = calculateV1(a, b)
// return oldResult

// ❌ 无意义的 TODO（没有原因、没有上下文）
// TODO 优化
// TODO fix this

// ❌ 情绪化 / 自嘲
// 这里写得很丑，以后再说
// 不知道为什么这样能跑，别动

// ❌ 与代码矛盾（比没有注释更糟）
// 按时间正序排列
return bills.sortedByDescending { it.time }
```

### 4.3 注释标记约定

统一使用大写前缀 + 冒号，便于全局搜索：

| 标记 | 用途 | 是否必须附带说明 |
|---|---|---|
| `// TODO:` | 待实现 / 待完善 | ✅ 必须写明**原因**与**触发条件** |
| `// FIXME:` | 已知缺陷，需修复 | ✅ 必须写明**复现条件** |
| `// NOTE:` | 重要说明，容易被忽略的约束 | ✅ 必须写明说明内容 |
| `// HACK:` | 临时绕过方案 | ✅ 必须写明**为什么**绕过、何时可移除 |
| `// PERF:` | 性能相关取舍 | ✅ 必须写明**省了什么 / 牺牲了什么** |
| `// ROM:厂商` | 厂商适配分支 | ✅ 必须写明**该厂商的差异点** |

示例：

```kotlin
// TODO: 补充招商银行短信模板。当前只有工行/建行样例，
//       等本机收到招行真实短信后再加（复用 SmsScanner 流水线）
// FIXME: 连续两笔相同金额消费（如两次 25 元）会被误判为重复而丢弃，
//        复现：60 秒内同一商户、同一金额的两笔真实消费
// HACK: OriginOS 会在 App 退到后台 3 秒后回收 RenderEffect，
//       这里重新 attach 一次。等 vivo 修复系统 bug 后可移除（预计 Android 16）
// NOTE: 修改此正则后必须同步更新 DefaultParseRules 中的版本号，否则旧数据不会重解析
```

### 4.4 行注释格式

| 规则 | 说明 |
|---|---|
| 位置 | 优先放在**被解释代码的正上方**；仅在解释短语时放行尾 |
| 行尾注释 | 与代码之间空 **2 个空格**，且该行总长不超过 120 |
| 空行 | 注释与其上方代码之间**不空行**，与上方逻辑块之间可空行 |
| 语言 | 中文（项目为个人自用，中文表达更准确） |
| 标点 | 完整句子以句号结尾；短语可省略 |
| 长度 | 单行不超过 120 字符，超出换行并缩进对齐 |

```kotlin
// ✅ 正确
// 月末最后一天：剩余额度全部给今天
val todayAvailable = monthRemaining

val maxRetries = 3  // 超过 3 次说明服务已被系统杀死，重试无意义

// ❌ 错误
//月末最后一天：剩余额度全部给今天        // 冒号后缺空格
val todayAvailable = monthRemaining       // 缺少上方注释与代码的分隔
```

## 5. 类、字段与枚举注释

### 5.1 类级 KDoc

说明**这个类的职责与边界**，而非罗列方法：

```kotlin
/**
 * 所有账单来源的统一入库入口。
 *
 * 职责边界：
 * - **负责**：字段归一化、金额转「分」、去重判定、落库
 * - **不负责**：采集（由各 [BillSource] 实现）、规则维护（由 [RuleEngine] 负责）
 *
 * 所有来源都必须经过这里，以保证去重与归一化逻辑只有一份实现。
 *
 * @property billRepository 账单仓储
 * @property ruleEngine 解析规则引擎
 */
class BillIngestor @Inject constructor(
    private val billRepository: BillRepository,
    private val ruleEngine: RuleEngine
) { ... }
```

### 5.2 Entity 字段注释

**有业务含义的字段必须注释**，尤其是设计预留字段：

```kotlin
@Entity(tableName = "bill")
data class BillEntity(
    /** 金额，单位「分」，恒为正数；正负语义由 [type] 决定 */
    val amountCents: Long,

    /** 账单类型：支出 / 收入 / 转账 */
    val type: BillType,

    /**
     * 是否计入统计与预算。
     *
     * 设计说明：把「是否计入」从类型中剥离成独立开关，是为了覆盖
     * 「转账还款不计入」「借给朋友的钱要算支出」「可报销先不计入」等
     * 所有边界场景，避免将来反复改表。
     *
     * 默认值：[BillType.EXPENSE] / [BillType.INCOME] 为 true，[BillType.TRANSFER] 为 false。
     */
    val countInStats: Boolean,

    /** 交易发生时间（毫秒）。**不是记录时间**，补记场景必须用真实交易时间 */
    val time: Long,

    /** 原始通知/短信全文。用于排查解析失败，以及规则更新后的批量重解析 */
    val rawText: String?,

    /** 去重哈希：md5(金额 + 分钟级时间 + 归一化商户)，建唯一索引防重复 */
    val dedupHash: String,

    /**
     * 分类 ID。
     *
     * 预留说明：当 [type] 为 [BillType.TRANSFER] 时，本字段复用为
     * 「还款 / 账户互转 / 借款」等转账子类型，同样不参与统计。
     */
    val categoryId: Long
)
```

### 5.3 枚举注释

```kotlin
/**
 * 账单类型。
 *
 * 注意：类型**不决定**是否计入统计，是否计入由 [Bill.countInStats] 单独控制。
 */
enum class BillType {
    /** 支出，默认计入统计与预算 */
    EXPENSE,

    /** 收入，默认计入统计 */
    INCOME,

    /**
     * 转账 / 还款 / 借贷，默认**不计入**统计。
     *
     * 典型场景：银行卡还信用卡、支付宝转银行卡、可报销的垫付款。
     * 若某笔转账确实要计入（如借给朋友的钱想算支出），
     * 把 [Bill.countInStats] 置为 true 即可。
     */
    TRANSFER
}
```

## 6. Kotlin 编码规范

### 6.1 不可变优先

```kotlin
// ✅ 优先 val、不可变集合、data class copy
data class Bill(val amountCents: Long, val note: String?)
val updated = bill.copy(note = "新备注")

// ❌ 避免可变状态外泄
var amount: Long = 0                      // 除非确有必要
val list: MutableList<Bill> = mutableListOf()  // 公开 API 不要暴露可变类型
```

### 6.2 空安全

```kotlin
// ✅ 使用 ?.let / Elvis 提供默认值
val merchant = parsed.merchant ?: UNKNOWN_MERCHANT

// ✅ 需要非空时用 require / check 提前失败，并写明原因
require(amountCents > 0) { "金额必须为正数，收到：$amountCents" }

// ❌ 禁止 !!（除非能 100% 保证非空，且必须加注释说明为什么安全）
val name = bill.merchant!!   // ❌
// 若确有必要：
val name = bill.merchant!!   // NOTE: 此处 merchant 已在 RuleEngine 中做过非空校验
```

### 6.3 作用域函数选择

| 函数 | 使用场景 | 示例 |
|---|---|---|
| `let` | 非空时才执行 / 转换 | `bill.merchant?.let { parse(it) }` |
| `apply` | 对象初始化配置 | `Bill(...).apply { note = "x" }` |
| `run` | 需要返回值的配置块 | `val r = rule.run { match(text) }` |
| `also` | 副作用（日志、埋点） | `.also { Log.d(TAG, "$it") }` |
| `with` | 对同一对象多次调用（少用） | — |

### 6.4 协程

```kotlin
// ✅ ViewModel 统一用 viewModelScope
viewModelScope.launch { ... }

// ✅ 耗时计算切到 Default，并在注释中说明原因
// PERF: 短信增量扫描与正则批量匹配是 CPU 密集任务，必须切到 Default，否则会阻塞主线程导致掉帧
withContext(Dispatchers.Default) { ... }

// ✅ Flow 在 UI 层用 stateIn 转成 StateFlow，指定超时策略
val uiState: StateFlow<HomeUiState> = combine(...) { ... }
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), HomeUiState.Loading)

// ❌ 禁止 GlobalScope
GlobalScope.launch { ... }   // 泄漏风险
```

### 6.5 其他

| 规则 | 说明 |
|---|---|
| `when` 用于枚举 | **必须穷尽分支**，不使用 `else`（编译期保证新增枚举时报错） |
| 字符串拼接 | 优先字符串模板 `"¥${amount / 100.0}"`，而非 `+` |
| 数字字面量 | 用下划线提升可读性：`60_000L`、`1_000_000` |
| 集合操作 | 链式调用超过 3 步时换行，一步一行 |
| 异常 | 业务异常用 `IllegalArgumentException` + 中文消息；不要吞掉异常 |

## 8. 分层编码规范

| 层 | 强制要求 |
|---|---|
| `domain` | **禁止 import `android.*`**；只用 `kotlin.*` + `javax.inject.*`；模型全部 `val` |
| `data` | Entity ⇄ Domain 转换只能出现在 `data/mapper`；DAO 不对外暴露 Entity |
| `feature` | 禁止依赖 `data`；禁止直接操作数据库；所有数据经 `UseCase` 或 `Repository` |
| `core:design` | 禁止依赖 `domain`；组件只接收 `Color`/`Dp`/`String` |
| `app` | 只做壳与 DI 绑定，禁止写业务逻辑 |

```kotlin
// ❌ 反例：feature 层直接碰数据库（违反铁律 2）
@HiltViewModel
class HomeViewModel @Inject constructor(
    private val billDao: BillDao        // ❌ 应注入 BillRepository
) : ViewModel()

@HiltViewModel
class HomeViewModel @Inject constructor(
    private val observeBillsUseCase: ObserveBillsUseCase
) : ViewModel()
```

## 9. 格式化与文件组织

### 9.1 基础格式

| 项 | 规则 |
|---|---|
| 缩进 | 4 空格（禁止 Tab） |
| 单行长度 | 上限 **120** 字符 |
| 换行 | 参数超过 3 个或单行超限时，每个参数占一行 |
| 尾随逗号 | 多行参数列表**必须**带尾随逗号（便于 diff） |

```kotlin
class XxxViewModel @Inject constructor(...) : ViewModel() {

    // 1. 常量（companion object 放最后）
    // 2. 注入的成员变量
    // 3. 可变状态（private MutableStateFlow）
    // 4. 对外状态（StateFlow）
    // 5. init 块
    // 6. 公开方法
    // 7. 私有方法
    // 8. companion object
}
```

### 9.3 文件组织

- 一文件一类为主；强相关的密封类子类型、小型 `data class` 可同文件
- 文件名必须与主类名一致
- `feature/xxx` 固定四件套：`XxxScreen.kt` / `XxxViewModel.kt` / `XxxUiState.kt` / `components/`
